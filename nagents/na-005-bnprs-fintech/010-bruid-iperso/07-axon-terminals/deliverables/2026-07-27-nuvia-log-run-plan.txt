BNPRS perso-kiosk-agent — NUVIA EVIDENCE BUILD + RUN PLAN (2026-07-27)
======================================================================
Purpose: produce the four logs Nuvia asked for, in one comparable format.
They asked for (a) the time elapsed after the FINAL APDU under normal
operation, and (b) a Visa card driven through the desktop (HID/OMNIKEY)
reader, with the ENTIRE APDU log.

WHAT'S NEW IN THESE EXES
  1. Every log line now carries an absolute timestamp HH:MM:SS.mmm.
  2. Every APDU line reports gap=<ms> — host-side idle since the previous
     exchange returned — alongside the existing lat=<ms> (the IC_Input /
     SCardTransmit call itself).
  3. The feeder agent logs the time from the FINAL APDU to Card_EjectEx /
     Card_Control(reject) / IC_PowerOff, and how long the eject call took.
     That is Nuvia's question 1, measured.
  4. The PC/SC agent can now log FULL C-APDU and R-APDU BYTES (previously
     only length + INS + latency), so a desktop log and a feeder log can be
     diffed line for line. Gated behind PCSC_APDU_TRACE=1.

  PCI — READ THIS: the byte trace contains whatever the perso stream carries
  (PAN, track 2, PIN block, DEK-wrapped keys). Run these four tests with a
  TEST/DUMMY DPI and test keys only. Treat the logs as cardholder data until
  they are confirmed clean; check before sending anything to Nuvia.

BEFORE YOU START
  - The bureau security group allows only the kiosk's CURRENT public IP on
    9099. The kiosk IP is dynamic — confirm it still connects (a preflight

  - Cards are scarce. A run that fails mid-stream does NOT secure the card,

WHAT WE EXPECT (and what would change the diagnosis)
  Visa's one heavy command is DGI 9200 — about 0.9 s on the desktop reader.
  At the feeder's ~4x slower clock that lands near 3.5-4 s, the same zone
  where MasterCard's A004/A002 fail. So run D is expected to fail at 9200
  with 6985 while run C passes.
    - If D fails at 9200: confirms the fault tracks COMMAND DURATION, not
      card scheme or data — exactly what we told Nuvia.
    - If D passes completely: the scheme does matter and our clock/block-wait
      explanation is incomplete — send the logs before drawing conclusions.
